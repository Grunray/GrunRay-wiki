Vue3 前端，关于在某个页面内使用容器后没有出现滚动条的问题。

原因就是，容器的大小是根据容器内的内容来决定的，但是页面是不知道容器的大小的，所以只要告诉页面你容器的大小即可。

### 现象

页面切换到某个内容较多的 Tab 后，内容无法上下滑动，也看不到滚动条（PC 和手机均如此）。

### 原因

滚动发生在「知道自身高度」的容器上：只有容器高度是确定的（例如由视口或 flex 分配出来），`overflow-y: auto` 才会产生滚动条。

之前的结构是：外层（页面容器 / Tab 外层）没有固定高度，而 Tab 内容区又被限制在内部（固定高度 + 内部滚动）。在部分环境里：

- 要么 flex 链没把高度一直传下去，内部「可滚动」的 div 实际高度没被限制；
- 要么外层容器随内容增高，「页面」本身没有固定高度，所以不会出现滚动条。

换句话说：容器按内容变高，但包含它的「页面」不知道容器有多大，所以没有可滚动的区域。

## 解决思路

让「包裹 Tab 的那一层」同时满足两点：

1. 有明确高度（例如 `flex: 1` + `min-height: 0` 在整页 flex 布局下得到剩余高度）；
2. 在这一层设滚动（`overflow-y: auto`），由它来当唯一的滚动容器。

内部（`van-tabs`、tab 内容）不再做「内部滚动」，高度完全由内容撑开。内容变多 → 整块 Tab 区域变高 → 超过外层固定高度 → 在外层出现滚动条并可滑动。

## 具体改动（简要）

- **外层 Tab 包裹容器**：`flex: 1`、`min-height: 0`（得到明确高度），并设 `overflow-y: auto`、`-webkit-overflow-scrolling: touch`、`touch-action: pan-y`，滚动只发生在这里。
- **van-tabs** / **van-tabs__content** / **van-tab__pane**：去掉固定高度和内部 `overflow`，让高度由实际业务内容自然撑开。
- **内容组件**：去掉「内部滚动容器」的样式，只做普通内容块，参与撑高 Tab 区域。

## 可记结论

谁有固定高度，谁设 `overflow-y: auto`，谁才能出现滚动条。

若希望「整块区域可滑动」，就应让外层有固定高度并成为滚动容器，内层只负责变高，不要在外层高度未定的情况下再在内部做一层「理论上的」滚动。

## 注意事项

- 导航与滚动条视觉重叠属于布局取舍；若需避免，可将导航移出滚动层或调整 `z-index` / 布局分区，与「唯一滚动容器」原则不冲突。
