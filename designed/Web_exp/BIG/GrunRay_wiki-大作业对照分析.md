# GrunRay Wiki × Web 前端大作业要求对照分析

> **对照依据**：[要求.md](./要求.md)  
> **项目仓库**：`GrunRay_wiki`（Vue 3 前端 + Flask/MySQL 后端）  
> **小组规模**：3 人 — 作业说明中「基本要求 × 组内人数」，下文 **【三人组】** 标注按 **×3** 折算后的门槛。

---

## 一、项目与选题（总体）

| 要求要点 | 状态 | 说明 |
|----------|------|------|
| 主题不限，需有实用性/完整场景，非纯静态展示 | ✅ 满足 | 个人 Wiki：项目展示、算法博客、留言板、友链申请等，有明确用户场景（访客浏览、留言、申请友链；站长审核）。 |
| 鼓励 Vue 组件化 | ✅ 满足 | Vue 3 + `<script setup>` + 多视图/组件拆分。 |
| 可纯前端 + JSON/localStorage/API；也可用后端 | ✅ 满足（偏强） | 实际为 **前后端分离**：前端调 `/api/*`，后端 MySQL + Markdown 导入；符合作业「调用公开 API / Mock / 本地 JSON」的延伸形态，但 **答辩与文档需写清依赖 MySQL 与 `.env`**，避免助教按「仅静态+JSON」验收时跑不起来。 |

**选题与需求分析（评分 10 分）**：题材与实现匹配度高；需在 **设计文档** 中单独写清背景、用户与需求（见第五节待办）。

## 三、技术要求逐项

### 3.1 HTML5 语义化

| 要求 | 状态 | 说明 |
|------|------|------|
| 合理使用 `header` / `main` / `nav` / `article` / `section` 等 | ✅ | 各 View 与 `SiteNav` 等使用语义标签；根节点为 Vue 挂载 `#app`（SPA 常见做法）。 |
| 不能全是 div 堆砌 | ✅ | 列表/详情/留言/友链页均有语义结构。 |

### 3.2 CSS3

| 要求 | 状态 | 说明 |
|------|------|------|
| Flex / Grid 布局 | ✅ | 如 `main.css` 中 `.app-root`、各页面 `display: flex/grid`。 |
| 风格统一、层次清晰 | ✅ | CSS 变量主题、`themes/*.css`、统一 card/时间轴样式。 |
| ≥3 种 CSS3 效果 | ✅ 远超 | 已用：`border-radius`、`box-shadow`、`transition`、`transform`、`animation`、`@keyframes`、渐变/变量背景、`:hover` / `:focus-visible`、`@media` 响应式与 `prefers-reduced-motion` 等。 |
| PC 端无明显错位 | ✅ 基本 | 需在答辩录屏中 **逐页展示** 留言/友链/博客窄屏情况。 |
| 鼓励响应式 | ✅ 部分 | 主要页面有断点；复杂组件（导航、音乐播放器）建议在文档中附 **手机宽度截图** 说明取舍。 |

### 3.3 JavaScript 与 jQuery

| 要求 | 状态 | 说明 |
|------|------|------|
| DOM 动态更新 | ✅ | 通过 Vue 响应式与列表渲染实现（等价于传统 DOM 操作）。 |
| 事件处理（点击/输入/提交/切换/删除/添加） | ✅ | 留言提交、审核、友链表单、博客筛选、音乐控制等。 |
| 表单获取、校验、反馈 | ✅ | `FriendsApplyView`、`MessagesView` 含前后端校验与 toast/错误提示。 |
| 列表渲染 + 搜索/筛选/排序/分页至少一种 | ✅ | 博客/项目：**筛选**；留言：**排序**；列表 **动态渲染**；后端 API 支持分页参数（前端部分列表一次拉取较多条）。 |
| 若使用 jQuery… | ➖ 不适用 | 项目 **未使用 jQuery**（全站无业务依赖）。作业原文为「若使用」；**用 Vue 3 覆盖 JS 能力即可**，建议在实验报告「技术方案」中说明：**未采用 jQuery，采用 Vue 组合式 API 替代**。 |
| 禁止仅静态 HTML | ✅ | 动态数据来自 API + 部分 session/local 缓存。 |

### 3.4 Vue

| 要求 | 状态 | 说明 |
|------|------|------|
| Vue 2 或 Vue 3 | ✅ | Vue **3.5** + TypeScript。 |
| 合理划分组件 | ✅ | 导航、卡片、留言头像、项目块、骨架屏、音乐播放器等。 |
| 数据绑定、事件、条件/列表渲染 | ✅ | 全站普遍使用。 |
| Vue Router | ✅ | `frontend/src/router/index.ts`，10+ 路由。 |
| Pinia / Vuex | ✅ 鼓励项 | **Pinia**（`stores/ui.ts`）管理主题、光标轨迹、音乐最小化等。 |
| Element Plus 等 UI 库 | ➖ 未用 | 作业为「鼓励」且要求 **不得只靠组件库堆砌**；当前为 **自研样式**，符合要求；可在文档写明 **未使用第三方 UI 库的原因（定制视觉）**。 |

### 3.5 数据处理

| 要求 | 状态 | 说明 |
|------|------|------|
| 数据来源方式 | ✅ | 后端 API + DB；开发阶段 Markdown/JSON 导入脚本；前端 `sessionStorage` 缓存列表/详情。 |
| 数据操作至少 **2 类**（增删改查筛排统视） | ✅ 多项 | **新增**：留言、友链申请；**查询**：文章/项目/留言/友链列表；**筛选**：博客分类/标签/关键词、项目标签；**排序**：留言时间正/倒序；**修改**：站长回复留言；**删除/隐藏**：留言/友链 **审核**（approve/reject/hide 等）。 |
| 统计或可视化 | ⚠️ 偏弱 | 留言有 `total` 等计数展示，**无图表库（如 ECharts）或独立统计页**；胶片/时间轴偏展示而非「数据统计」。**【三人组】** 建议在文档与界面中 **补 1 块轻量统计**（如：文章数/项目数/留言数概览卡片，或简单 CSS 条形图）。 |
| localStorage 持久化 | ✅ 部分 | 语言、主题、音乐状态、播放器位置等；**业务数据（留言/友链）在服务端**，刷新仍保留，但需跑通后端。 |
