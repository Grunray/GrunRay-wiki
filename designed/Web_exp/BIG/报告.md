一、项目概述

项目名称：GrunRay Wiki（个人 Wiki / 作品集站点）

项目背景：
课程要求完成一个具有明确主题、可交互、能处理数据的前端应用。本小组将平时持续维护的个人站点 GrunRay Wiki 作为大作业载体：站点集项目展示、算法与工程博客、留言互动、友链展示与申请于一体，既满足课程技术指标，也可作为长期作品集继续迭代。

开发目的：
（1）为访客提供统一的浏览入口，了解作者的项目与文章；
（2）支持访客留言、申请友链等轻量互动；
（3）为站长（站点所有者）提供留言与友链的审核、回复能力；
（4）通过 Vue 3 组件化与数据驱动布局，实践前端工程化与较完整的交互体验。

目标用户：
（1）普通访客：浏览首页、项目、博客，发表留言，提交友链申请；
（2）站长（管理员）：通过 OAuth 登录后审核留言、回复留言、审核友链申请（前端体现为留言页「待审核」等能力）。

应用场景：
个人品牌展示、竞赛与课程项目归档、算法笔记发布、访客社交互动（留言/友链）。本作业答辩与验收以 Web 前端实现为主，数据通过本地运行的 API 获取（课程范围内可将后端视为数据服务，不计入三人前端分工细节）。

小组规模：3 人；功能模块与页面数量按课程要求乘以 3 执行。


二、需求分析

2.1 要解决的问题
（1）信息分散：项目、文章、外链原先分散在多处，需要一站聚合；
（2）展示单调：纯静态列表难以体现作品差异，需要可嵌入 Demo 的项目详情；
（3）互动缺失：需要留言与友链机制，并防止垃圾内容（验证码、审核）；
（4）体验要求：课程要求非纯静态页，需筛选、表单、反馈、持久化偏好等交互。

2.2 功能需求
（1）首页：站点介绍、精选入口、胶片式媒体展示、外链复制；
（2）项目：时间轴列表、标签筛选、详情页（概述/演示/图集/更新日志/Markdown 等块）、关联笔记；
（3）博客：分类与标签及关键词筛选、时间轴列表、文章详情（Markdown 渲染）；
（4）留言：列表展示、发表（字数校验、验证码）、按时间排序、站长审核与回复；
（5）友链：已通过友链展示、友链申请表单（校验、验证码、预览头像）；
（6）扩展页：碎语/推荐/关于等全屏视图（碎语等页复用「栖息」分栏布局，与全站壳层一致）；
（7）404 互动页：故障风文案抖动、全站「损坏」视觉态、解锁并切换隐藏「抽象」主题、重播故障动画、返回首页；
（8）全局：导航切换、中/英语言、日/夜/抽象主题、可选页面背景图、浮动音乐播放器、光标轨迹等偏好设置。

2.3 非功能需求
（1）界面友好：统一色彩与圆角卡片风格，主题可切换，关键操作有 Toast 或错误提示；
（2）易用性：表单必填与格式校验，加载过程有骨架屏，减少白屏；
（3）兼容性：面向常见 PC 浏览器；主要页面具备响应式断点（如窄屏下时间轴与 Demo 区域高度调整）；
（4）可维护性：Vue 单文件组件按 views / components / services 分层；项目详情采用 layout 块注册表，新增块类型无需改路由；
（5）无障碍与动效：支持 prefers-reduced-motion，用户开启系统「减少动画」时跳过入场动画与部分动效；
（6）安全性（前端侧）：Demo 使用 iframe sandbox；用户提交内容经后端校验，前端配合 DOMPurify 渲染 Markdown。

2.4 用户角色说明
（1）普通访客：可浏览全部公开内容，可发表留言、提交友链申请，不可审核他人内容；
（2）站长：在留言模块登录后可见待审核列表，可批准/拒绝留言、发表站长回复；友链审核可在管理流程中完成（前端以申请成功提示为主，审核结果由数据状态决定）。
非站长用户不具备管理面板，角色通过登录态与接口返回的 isSiteOwner 等字段区分。

四、页面设计

本项目为 Vue 单页应用，通过 Vue Router 实现不少于 9 个视图（三人组要求）。主要页面如下：

（1）首页 /
    内容：站点标题、标语、社交外链（含邮箱复制）、首页胶片 Feed 媒体展示。
    功能：进入项目/博客等入口；媒体点击放大查看；支持页面入场动画。

（2）项目列表 /projects
    内容：按年份分组的时间轴项目卡片。
    功能：按标签筛选；点击进入项目详情。

（3）项目详情 /projects/:slug
    内容：标题、摘要、标签、外链；按 layout 配置顺序渲染多块（概述、Demo、图集、changelog、Markdown 等）。
    功能：站内嵌入 Demo（iframe）；跳转项目笔记、GitHub 等。

（4）项目笔记 /projects/:slug/notes
    内容：与该项目关联的笔记/文章列表。
    功能：跳转博客详情阅读。

（5）博客列表 /blog
    内容：文章时间轴。
    功能：分类（全部/杂项等）、标签下拉筛选、关键词搜索；缓存列表以提升返回体验。

（6）文章详情 /blog/:slug
    内容：标题、元信息、Markdown 正文。
    功能：代码块一键复制；SEO meta 更新。

（7）留言 /messages
    内容：发表区、公开留言列表；站长登录后可见待审核 Tab。
    功能：验证码、字数限制、新/旧排序；站长批准/拒绝/回复。

（8）友链 /friends
    内容：普通友链与特殊样式友链。
    功能：跳转申请页。

（9）友链申请 /friends/apply
    内容：站点名、URL、描述、邮箱、头像等表单与预览。
    功能：前端校验、验证码、提交申请。

（10）碎语 /fragments、撰写 /fragments/compose、推荐 /recommend、关于 /about
    内容：扩展个人化页面（列表+详情分栏或全屏排版）。
    功能：筛选、排序、详情滑入（栖息分栏布局 XiqiSplitLayout）。

（11）404（任意不存在路径，如 /this-route-does-not-exist）
    内容：大号 404 标题与说明文案；非抽象主题下文案周期性「损坏」抖动（corruptText）；信号框与标题故障动画（CSS keyframes）；提示可解锁隐藏主题。
    功能：
    a）进入未注册路由时自动触发全站 page-corrupt 视觉态（与 theme/pageCorruptState 联动）；
    b）「解锁主题」：将隐藏「抽象」主题写入 localStorage，此后主题切换器可出现第三套主题；
    c）「应用抽象主题」：一键切换到抽象主题并停止故障动画，页面进入稳定排版；
    d）「重播故障」：已解锁用户可再次播放约 8 秒故障动画（抽象主题下自动结束）；
    e）「返回首页」RouterLink；
    f）SEO：noindex/nofollow，避免无效 URL 被收录。
    说明：404 不是空白占位页，而是带彩蛋与主题解锁的完整交互视图（NotFoundView.vue）。

说明：答辩材料中建议对每个主路径附 1 张截图；项目详情页需额外截 Demo 嵌入效果；404 建议截「故障态」与「解锁抽象主题后」各一张。


五、交互流程设计

5.1 访客浏览内容（项目/博客）
步骤 1：打开站点，进入首页，浏览介绍与胶片媒体。
步骤 2：点击导航「项目」或「博客」。
步骤 3：在列表页使用标签/分类/关键词缩小范围。
步骤 4：点击某一条进入详情页阅读；若在项目详情，可打开嵌入 Demo 或跳转外链。
步骤 5：通过导航返回或浏览器后退继续浏览。

5.2 访客发表留言
步骤 1：进入留言页，填写正文（系统显示字数）。
步骤 2：完成验证码题目，点击提交。
步骤 3：前端校验通过后调用接口；成功则 Toast 提示并刷新列表（若开启审核则显示待审核说明）。
步骤 4：可在列表切换「最新/最早」排序查看结果。

5.3 站长审核留言（可选演示）
步骤 1：站长在留言页通过 GitHub/Google OAuth 登录。
步骤 2：切换到「待审核」Tab，查看待处理留言。
步骤 3：执行批准或拒绝；可对已通过留言填写站长回复并提交。
步骤 4：列表刷新，访客在公开 Tab 可见已发布内容。

5.4 访客申请友链
步骤 1：从友链页进入申请页。
步骤 2：填写站点信息，系统根据 URL 尝试预览 favicon。
步骤 3：完成验证码并提交；成功显示提示（待站长审核后展示在友链列表）。

5.5 404 彩蛋与隐藏主题（可选演示）
步骤 1：在地址栏输入不存在的路径，进入 404 页，观察文案损坏抖动与全站故障视觉。
步骤 2：点击「解锁主题」，将隐藏「抽象」主题写入本地偏好。
步骤 3：点击「应用抽象主题」，切换至抽象主题，故障动画停止，页面稳定展示。
步骤 4：可点击「重播故障」再次体验动画；或点击「返回首页」离开。

5.6 偏好设置（贯穿多页）
步骤 1：在顶栏切换中/英文、日/夜主题、页面背景图开关等。
步骤 2：设置写入 localStorage，刷新后仍保留；音乐播放器位置与音量同理。

七、技术方案设计

7.1 HTML5
使用 header、nav、main、section、article、footer 等语义标签构建各页面骨架；SPA 根节点为 div#app。表单使用 label、输入控件与 aria-labelledby 提升可读性。

7.2 CSS3
采用 Flex 与 Grid 完成全站与首页、时间轴、栖息分栏布局；CSS 变量实现日/夜/抽象三套主题 token；广泛使用 border-radius、box-shadow、transition、transform、animation、@keyframes、渐变与伪类；按断点 @media 适配窄屏；page-enter-*.css 实现分页面入场动画；404 页 not-found-title-glitch、not-found-frame 等故障动画；styles/themes/page-corrupt.css 实现全站「损坏」覆盖层。

7.3 JavaScript
在 Vue 组合式 API 下完成事件处理、表单校验、列表筛选排序、异步请求与错误反馈；composables 封装入场动画、复制、顶栏 FLIP、导航 compact 等逻辑。本项目未使用 jQuery，DOM 更新由 Vue 响应式与模板编译承担，能力上覆盖课程对 DOM 操作与事件处理的要求。

7.4 Vue 3
使用 script setup、ref/computed/watch、组件化拆分（布局、卡片、块渲染器、业务页）；条件渲染与列表渲染贯穿列表页与留言 feed。

7.5 Vue Router
配置十余条子路由，AppShell 为父组件；scrollBehavior 回顶；afterEach 中切换页面背景图与特殊视觉态。

7.6 Pinia
ui store 管理主题、照片背景、音乐最小化、光标轨迹等全局 UI 状态，并与 localStorage 同步。

7.7 localStorage / sessionStorage
localStorage：语言、主题、音乐播放器；sessionStorage：博客列表/详情短期缓存，减轻返回时闪烁。

7.8 其它库（说明用途，非 UI 组件库堆砌）
vue-i18n：中英文案；marked + DOMPurify：Markdown 安全渲染；GSAP：光标轨迹字符动画；@unhead/vue：页面 SEO meta。未使用 Element Plus 等成品 UI 库，界面为自定义设计。
未使用 ECharts；数量类信息以列表 total 与文案概览为主，后续可增加统计卡片。

7.9 数据获取方式
前端通过 fetch 封装访问 /api 下只读与提交接口（contentRepository、messageApi、friendsApi 等）；开发阶段内容由 Markdown 导入后端，答辩时启动本地 backend + frontend 即可演示。

7.10 项目 Demo 容器机制（本项技术难点）
demos 目录下各子工程含 demo.config.json；npm run build:demos 调用 build-demo-assets.mjs 构建静态或 Vue 子项目并输出到媒体目录；项目详情 layout 中 type 为 demo 的块由 DemoBlock.vue 以 sandbox iframe 加载 demoUrl 或 srcdoc，实现「主站嵌作品」。

九、总结与不足

9.1 完成情况
本项目作为三人组 Web 前端大作业，在页面数量、功能模块、Vue 技术栈、表单与列表交互、数据新增/查询/筛选/排序及站长侧审核等方面均达到并超过课程基本要求；视觉与动效投入较多，体现个人作品集定位。

9.2 小组收获（可按人拆分写入终稿）

成员丙：掌握友链业务表单与展示组件、多模块联调测试、实验文档与答辩编排。

9.3 存在的问题与不足
（1）统计与图表可视化较弱，尚未使用 ECharts 等做数据看板；
（2）普通访客无法编辑/删除自己的留言，管理动作集中在站长角色；
（3）全站依赖本地 API 与数据库，助教环境需按文档配置，否则仅前端无法展示动态数据；
（4）部分复杂动效在极低性能设备上仍可能吃力，虽已做 reduced-motion 降级；
（5）frontend 根目录 README 仍偏模板化，需与 backend 说明合并为一份作业提交用运行指南。
