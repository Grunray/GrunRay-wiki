## 第 3 页 · 项目背景与定位

这个项目不只是一篇博客，我想做的是把**个人博客、项目展示、社区互动、碎念随笔**这几件事放在一个站点里。

核心诉求有四条：

1. 展示前端工程化和交互设计能力；
2. 内容用 **Markdown**（一种用纯文本写文章的格式，写起来像记笔记，最后能渲染成排版好的网页）作为数据源，和界面 UI 分开，方便维护；
3. 在常规博客功能之上，做出一点差异化体验；
4. 覆盖课程要求里的 **CRUD**、路由、状态管理和动效。

> **CRUD** 是 Create、Read、Update、Delete 四个英文单词首字母的缩写，中文常说「增删改查」——就是数据的新增、读取、修改、删除，前端项目里基本都会涉及。

站点分成四大板块：

- **首页**：个人介绍和胶片流；
- **创作**：博客文章 + 项目展示；
- **社区**：留言板和友链；
- **栖息（Xiqi）**：短碎念、关于页、推荐页。

用户分三类（按权限从低到高）：

1. **访客（未登录）**：浏览、搜索、看留言和友链；友链申请填表单 + 验证码即可，**不需要登录**。
2. **OAuth 登录用户**：在留言板用 GitHub / Google 登录后的身份——可以发表、回复留言（同样要验证码和频控），头像和昵称跟账号绑定，比匿名可信。代码里叫 `guest_user`，和站长用的是同一套 OAuth，但**没有**审核、管理权限。
3. **站长**：也是 OAuth 登录，但 GitHub/Google 账号在白名单里（`.env` 配置）。额外能做内容导入、留言/友链审核、碎念撰写、媒体上传等。

> **OAuth**（Open Authorization）：用 GitHub、Google 等第三方账号授权登录，不用在本站单独注册密码。本站留言必须走 OAuth，是为了知道「是谁留的言」，也方便防 spam。

所以中间这类**算独立角色**——需求上值得单独写一行，不能和「访客能留言」混为一谈（实际上未登录是**不能**留言的，必须先 OAuth）。

## 第 4 页 · 博客需求分析

这一页是对博客模块做需求拆解，按优先级来排。

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 文章浏览 | 算法笔记、项目笔记、通用文章分类展示 | P0（最高，必须做） |
| 文章详情 | Markdown 渲染、代码高亮、复制、相关推荐 | P0 |
| 搜索 | 中文关键词搜索，后端用 **jieba** 分词 + 打分 | P0 |
| RSS 订阅 | 服务端生成 rss.xml，供阅读器订阅 | P1（次要，有时间再做） |
| SEO | 每路由配置 title、OG、JSON-LD | P1 |
| 内容管理 | Markdown 导入管线，不是在线 CMS | P0 |

> 几个词简单解释一下：

> - **jieba**：一个中文分词工具，把「前端开发课程」切成「前端 / 开发 / 课程」，搜索时比整句匹配更准。
> - **RSS**：一种订阅格式，读者可以用 Feedly 这类阅读器自动收到新文章，不用每天手动刷网站。
> - **SEO**（Search Engine Optimization）：搜索引擎优化，让 Google、百度更容易理解并收录你的页面。
> - **OG**（Open Graph）：分享到微信、Twitter 时显示的那张卡片预览图和标题，就是 OG 标签控制的。
> - **JSON-LD**：一种写在网页里的结构化数据格式，告诉搜索引擎「这是一篇文章，作者是谁、发布时间是什么」，有助于搜索展示。
> - **CMS**（Content Management System）：内容管理系统，比如 WordPress 那种后台在线写文章。我这个项目刻意不做在线 CMS，而是用 Markdown 文件 + 导入脚本，更贴近工程化写法。

## 第 5 页 · 功能需求总览

六大模块一句话概括：

1. **博客系统**：列表、详情、搜索、RSS；
2. **项目展示**：卡片列表、layout 块、Demo 嵌入；
3. **栖息 Xiqi**：碎念分栏、关于页、推荐页；
4. **社区互动**：留言板、友链申请与审核；
5. **全局壳层**：导航、主题切换、**i18n**、音乐播放器；
6. **内容管线**：Markdown 导入，**API** 只读分发。

> **i18n**（internationalization，国际化）：让网站支持多语言，比如中英文切换。  
> **API**（Application Programming Interface）：前后端约定的数据接口，前端通过它拿文章列表、提交留言等。

## 第 6 页 · 创新亮点概览

接下来是重点——在普通博客之上，我加了六块差异化体验：

| 创新点 | 一句话 |
|--------|--------|
| SVG 开屏动画 | 蜗牛路径行走 + iris 圆形揭幕 |
| Footer 页脚 | 滚动揭示 + slice 扭曲 |
| 项目 Demo | iframe 内嵌可交互演示 |
| 胶片首页 | 横向胶卷流 + 全屏预览 |
| 黑胶播放器 | 可拖拽 BGM + 摇杆音量 |
| 栖息分栏 | FLIP 动画的阅读器式交互 |

> **iframe**（inline frame，内联框架）：在网页里再「开一个小窗口」，嵌进另一个独立页面。项目 Demo 用它把 Three.js 演示包在博客文章里，主站和 Demo 代码互不干扰；配合 **sandbox** 还能限制 Demo 里的脚本权限，更安全。

## 第 7 页 · 创新点① SVG 开屏动画

开屏动画叫 **Splash Woniu**，左侧可以看到实际效果截图。

**素材来源**：开屏里的 SVG 矢量图形是我用 **Affinity Designer** 自己画的，不是网上找的素材包。Affinity 是一款矢量绘图软件，类似 Illustrator，适合画路径、图标这类可以无损缩放的图形。

**实现方案**：

1. 独立 **iframe**（网页里再嵌一个小网页）播放 SVG 路径动画，蜗牛沿路径行走；
2. 动画结束后用 **postMessage** 和主页面通信——这是浏览器提供的跨窗口消息机制，iframe 告诉主页「我播完了，你可以接手了」；
3. 螺旋壳的坐标映射到头像位置，再做 **iris** 圆形揭幕，像相机光圈打开一样过渡到首页；
4. 用 **sessionStorage**（浏览器会话级存储，关掉标签页就清掉）控制同一次访问只播一次；
5. 支持 **prefers-reduced-motion** 降级——这是系统无障碍设置，用户如果开了「减少动效」，我们就跳过或简化动画。

**课程价值**：矢量设计 + SVG 动画 + 跨 iframe 通信 + **GSAP** 时间轴编排。

> **SVG**（Scalable Vector Graphics）：可缩放矢量图形，用代码描述路径，放大不会糊。  
> **GSAP**：一个专业的前端动画库，可以精确控制「第 0.3 秒做什么、第 0.8 秒做什么」，比纯 CSS 复杂动画好编排。

## 第 8 页 · 创新点② Footer 页脚交互

页脚参考了 **Trae 官网**（trae.ai）的 Footer 设计，分两个交互：

**滚动揭示（Reveal）**  
页面滚到底部时，品牌字「GRUNRAY」逐片显现；底部有一条 Glass 风格的 meta bar，放 ICP 备案、RSS 订阅、外链导航。

> **Glass 风格**：类似 iOS 的毛玻璃效果，半透明、带模糊，看起来有层次感。

**指针扭曲（Distort）**  
鼠标靠近页脚时，品牌字被切成 20 片 **slice**，指针附近的几条横带会错位拖影——这个效果也是参考 Trae 官网 Footer 的拖影交互。技术上用 **FLIP** 布局加 **CSS transform** 实现。

> **FLIP**：First、Last、Invert、Play 的缩写，一种先记录元素起始位置、再算结束位置、中间用 transform 补间的高性能动画技巧，避免频繁改 layout 导致卡顿。

还和 **Xiqi 分栏**做了 **footer lock** 联动——分栏打开时锁住页脚，避免两个复杂动画抢滚动。

## 第 9 页 · 创新点③ 项目 Demo 嵌入

项目详情页不是写死的模板，而是 **Layout 块驱动**：

- 项目 YAML 的 **front matter**（Markdown 文件开头那段元数据，用 `---` 包起来）里有一个 `layout` 数组；
- `registry.ts` 注册块类型：overview、demo、gallery、changelog 等；
- 以后要加新的展示形式，改配置就行，不用动路由。

**DemoBlock** 能力：

- 用 **iframe** 嵌入 `demo_url` 或 `demo_embed_html`；
- 加 **sandbox** 安全策略，限制 Demo 里脚本的权限，防止恶意代码影响主站；
- 示例是 CRSEA 的 **Three.js** 交互演示。

**构建方式**（这页我后来补充的）：

```bash
npm run build:demos
```

Demo 构建产物输出到 `backend/content/media/demos/...`，再通过 `/api/media/files` 分发。

> **Three.js**：一个在浏览器里做 3D 图形的 JavaScript 库。  
> **YAML**：一种比 JSON 更好写的人类可读配置格式，用来描述项目元信息和 layout。  
> **sandbox**：iframe 的安全沙箱，比如只允许脚本运行、不允许弹窗或访问父页面 DOM。

## 第 10 页 · 其他创新补充（上）

**首页胶片流 FilmFeed**  
模拟胶卷穿孔的横向滚动媒体带，滚轮可以调速，点击能全屏预览，数据从媒体 **API** 动态加载。

碎念列表选中某条后，主栏用 **FLIP** 动画缩进，右侧展开详情，像阅读器一样的双栏交互，和页脚、入场动画都有联动。

## 第 11 页 · 其他创新补充（下）

**路由级照片背景**  
不同路由切换不同背景图，各页有独立的入场 CSS，复杂动效用 GSAP 时间轴编排。

**404 乱码彩蛋**  
访问不存在的页面时，非 abstract 主题下会触发 **Glitch** 视觉故障效果；abstract 主题里还藏了彩蛋解锁入口，增加站点记忆点。

> **Glitch**：故意制造的「信号干扰」「画面撕裂」那种故障美学效果。

**中文智能搜索**  
后端用 jieba 分词 + **TF-IDF**（一种统计词重要程度的算法）抽关键词，应用层做相关性打分，比简单 SQL LIKE 模糊匹配更适合中文。

**SEO 与结构化数据**  
首页和各路由通过 `useSeoMeta` 注入 **head** 标签；输出 **JSON-LD** 结构化数据，类型包括 BlogPosting、WebSite，方便搜索引擎理解页面性质。

## 第 12 页 · 通用前端需求

这一页是课程里常见、也必须做到位的能力，分三列：

**数据与 CRUD**  
- **RESTful API** 对接（用 axios 或 fetch 封装 HTTP 请求）；  
- 留言/友链：访客 Create，站长 Update/Delete；  
- 碎念撰写：站长表单 + 文件导入；  
- 列表分页、筛选、骨架屏加载态。

> **RESTful API**：一种常见的接口设计风格，用 URL 表示资源、用 GET/POST/PATCH/DELETE 表示操作，前后端协作的主流方式之一。  
> **骨架屏**：数据还没加载完时，先显示灰色占位块，避免白屏，体验更顺滑。

**交互与动效**  
- GSAP + CSS Keyframes 页面入场；  
- FLIP 动画（顶栏溢出面板、分栏、页脚）；  
- 主题切换 light / dark / abstract；  
- prefers-reduced-motion 降级。

**工程化与体验**  
- **Vue Router** 嵌套路由 + scrollBehavior（切换路由时滚到顶部）；  
- **Pinia** 全局状态（主题、音乐、背景图）；  
- **vue-i18n** 中英文切换；  
- 响应式布局 + SEO meta + JSON-LD。

## 第 13 页 · 技术选型

| 层次 | 技术 | 为什么选 |
|------|------|----------|
| 前端框架 | Vue 3 + TypeScript + Vite | Composition API、类型安全、热更新快 |
| 路由/状态 | Vue Router 5 + Pinia | 嵌套路由、全局 UI 状态 |
| 样式/动画 | Less + GSAP | 模块化 CSS、时间轴动画 |
| Markdown | marked + DOMPurify | 双轨渲染 + XSS 消毒 |
| SEO | @unhead/vue | 动态 head、OG、结构化数据 |
| 后端 | Flask + PyMySQL | REST API、Markdown 导入、jieba 搜索 |

补充几个词：

- **TypeScript**：JavaScript 的超集，加了类型检查，大项目不容易写错变量类型；
- **Vite**：新一代前端构建工具，开发时启动和热更新都很快；
- **Composition API**：Vue 3 推荐的组合式写法，逻辑可以按功能拆成 composable 复用；
- **HMR**（Hot Module Replacement）：改代码后浏览器局部刷新，不用整页重载；
- **DOMPurify**：把 Markdown 转 HTML 后，过滤掉恶意脚本，防止 **XSS**（跨站脚本攻击）；
- **Flask**：Python 的轻量 Web 框架，写 API 很快；
- **PyMySQL**：Python 连接 MySQL 数据库的驱动。

## 第 14 页 · 总结

## 附录 · 答辩可能被问到的点（备稿）

**Q：为什么内容不用在线 CMS，而用 Markdown 导入？**  
A：课程重点是前端工程和交互，内容更新频率对个人站来说不高；Markdown + Git 版本管理更可控，也和很多技术博客的工作流一致。

**Q：iframe 和 postMessage 安全吗？**  
A：Demo iframe 加了 sandbox；postMessage 会校验来源，只接受开屏页发来的约定消息，不会随便执行外部脚本。

**Q：Trae Footer 是抄袭吗？**  
A：参考的是交互思路（滚动揭示、局部拖影），视觉品牌、切片实现、和 Xiqi 分栏的联动都是自己的代码，设计稿在 `designed/footer/` 里有记录。

**Q：P0 和 P1 怎么理解？**  
A：P0 是 MVP 必须交付，没有就不能算完成；P1 是增强项，比如 RSS 和完整 SEO，时间紧可以后补但架构上已预留。
