为什么又写了一个 wiki

不想再依赖第三方笔记：文章、项目、胶片、留言都想放在自己库里，顺便把 SEO 和主题也自己控制。

整站按「编辑式纸面」来做：纸面不是玻璃，强调色只有一个墨绿，标题衬线、正文无衬线、元数据等宽。

内容不是手输的

所有文章和项目都从 backend/import 下的 Markdown 导入，带 YAML front matter。改文章 = 改文件 + 重跑脚本。

python content_tools/import_markdown_posts.py
python content_tools/import_projects.py
目标是「写作在编辑器里完成，网站只是展示层」。

项目页是布局驱动的

每个项目的 YAML 里带一个 layout 数组，overview / gallery / demo / changelog / markdown 都是 block，前端按顺序渲染，正文段落本身平铺，不再套卡片。

这样项目页可以长很不一一样，但阅读节奏是一致的。
