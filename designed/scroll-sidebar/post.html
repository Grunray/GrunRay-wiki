重学线段树：从模板到懒标记

把区间修改拆成「不下传就记住」之后，代码短了一半，也没那么容易写挂了。这篇记一下从朴素写法到懒标记的过渡。

为什么又回来写线段树

第一次学的时候只会抄模板，区间加、区间求和背得滚瓜烂熟，一到要下传标记就开始抖。后来才明白，懒标记不是优化，是把「以后会做」改成「现在先记账」。

这篇用同一道题（P3372）从朴素写法一路改到带懒标记的版本，每一步都保留可提交的代码。

先把查询写对

查询没有标记要管，逻辑最短。很多同学先写修改再写查询，改到后面查询也带一堆 pushdown，反而乱。

long long query(int p, int l, int r, int x, int y) {
    if (x <= l && r <= y) return sum[p];
    pushdown(p, l, r);
    int mid = (l + r) >> 1;
    long long ans = 0;
    if (x <= mid) ans += query(p << 1, l, mid, x, y);
    if (y > mid) ans += query(p << 1 | 1, mid + 1, r, x, y);
    return ans;
}
pushdown 只在「要继续往下走」的时候调用，叶子节点不需要。

懒标记到底记什么

对区间加来说，标记就是「这个整段还要再加多少」。记的是还没下传的部分，不是累计总和。

写的时候可以问自己：如果这一层再也不被访问，这个值留在当前节点对不对？对，就对了。

常见挂点

1. 标记下传后忘了清零；2. pushdown 里先改儿子再改标记，顺序反了；3. 区间赋值和区间加混用时不处理覆盖关系。

这些在调试时都很疼，不如写的时候就用同一套模板，少自由发挥。

最后

线段树不难，难的是忍住不提前优化。先把朴素版本写稳，再一格一格往上加功能。
